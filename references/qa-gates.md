# 四道闸门

**PPT 里没有肉眼能查的文本框。** 文字溢出时 LibreOffice 会静默裁掉（导出的 PDF 里
根本看不到多余那几行），PowerPoint 里则直接把字漏到框外。所以闸门不是可选项。

每道闸门抓不同的一类问题，互不重叠：

| 闸门 | 输入 | 抓什么 | 唯一能抓的 |
|---|---|---|---|
| `qa_fit.py` | 版面清单 JSON（源码几何） | 文字溢出 / 贴身、表格压页脚、图片拉伸、越界 | **渲染后查不出的文字溢出** |
| `qa_pdf.py` | 渲染 PDF | 越界、压页脚、文本行重叠、图片拉伸、稀页、字体内嵌 | 真实落位的碰撞 |
| `qa_visual.py` | 渲染 PDF | 逐片段对比度、文字出框 | 颜色（前两道都看不到） |
| `qa_layout.py` | 渲染 PDF | 文字越出组件边界、大空隙、提前收工、偏空 | 好不好看 |

一键跑：

```powershell
python scripts\verify_all.py
python scripts\verify_all.py --soffice "C:\Program Files\LibreOffice\program\soffice.exe"
python scripts\verify_all.py --skip-build --skip-render     # 只重跑闸门
```

单独跑：

```powershell
python scripts\qa_fit.py    out\我的汇报_layout.json
python scripts\qa_pdf.py    out\render\我的汇报.pdf --manifest out\我的汇报_layout.json
python scripts\qa_visual.py out\render\我的汇报.pdf
python scripts\qa_layout.py out\render\我的汇报.pdf
```

改了任何东西——文案、配色、母版、闸门阈值——**都要重跑一遍**。

## 闸门一：qa_fit（源码几何）

**输入是 `kit.save_deck()` 落下的 `*_layout.json`**，它记着每个文本框的真实坐标、
逐 run 的字号与字重。这个文件是交付物的必要组成部分，不是调试产物。

### 字宽模型

- **西文**：用**真实字体文件实测**（pillow 打开 TTF，`getlength / em`）。
  换字体时经验系数就全错了，而这道闸门是唯一能在渲染前抓到溢出的地方。
  量不到（pillow 缺失或字体没装）会退回解析模型，并在输出里**明确列出**哪些字体是退回的。
- **中文**：统一 1.0em——实测标定值。一条 25 字（含全角引号）14.5pt 的中文文本
  渲染后宽 5.04in，即 0.2016in/字 = 1.0em。旧值 0.97 低估 3%，会少算一行、漏掉换行。
- **行高**：`行距 = 字号 × 行距倍率 × 1.22`，单行墨迹高 `1.32em`。
  所需高度 = `(行数-1) × 行距 + 最后一行的墨迹高`，**不是** `行数 × 行距`
  ——最后一行后面没有行距，用行数会凭空多出一整个行距。

### 阈值（都在文件顶部）

| 常量 | 默认 | 含义 |
|---|---|---|
| `TOL` | 0.08in | 溢出容差。文本框不是裁切窗口，字略超框不会裁掉，闸门二只认真实碰撞 |
| `TIGHT` | 0.03in | 低于这个余量算「贴身」，只提示不算缺陷 |
| `STRETCH` | 2% | 图片长宽比偏差超过此比例算拉伸 |
| `PAD` | 0.02in | 水平余量（文本框 inset 已置 0） |

**调阈值的顺序**：先看是不是量错了（字体退回解析模型了没），再考虑改阈值。
把 `TOL` 调大来消错误报，等于把闸门关掉。

## 闸门二：qa_pdf（渲染后几何）

必须用 `--manifest`（或 `--foot-text`）告诉它页脚那句口号，否则页脚会被误报成
「压页脚」——它本来就画在页脚带里。

| 常量 | 默认 | 含义 |
|---|---|---|
| `EDGE` | 2.0pt | 越界容差 |
| `MIN_OVERLAP` | 0.22 | 重叠面积 / 较小块面积 |
| `STRETCH` | 2% | 图片比例偏差 |
| `MIN_CHARS` | 40 | 低于此字数判稀页 |
| `FOOTER_BAND_TOP` | 6.98in | 页脚带起点 |

**重叠按行框算，不按块框算。** PyMuPDF 的 block 是它自己做的分组，块框是组内所有行
的并集——并排的左右两栏会被合成一个大框、互相「重叠」，三栏卡片页、图组页、
双列清单全是这种假阳性。行框（`line bbox`）才是眼睛实际看到的墨迹范围。

图片拉伸核对**不需要外部宽高比表**：放置比例和原图像素比例都能从 PDF 里读到。

## 闸门三：qa_visual（对比度与出框）

| 常量 | 默认 | 含义 |
|---|---|---|
| `LARGE_MIN` | 3.0 | 大字（≥18pt，或 ≥14pt 粗体）对比度门槛 |
| `SMALL_MIN` | 4.5 | 小字对比度门槛 |
| `CARD_W/H` | 120×60pt | 「卡片」的最小尺寸。低于此不当作文字的底 |
| `MARGIN` | 1.6pt | 判定出框的容差 |
| `DPI` | 150 | 像素兜底的渲染分辨率 |
| `BG` | 白 | 页面底色。深底主题改这里 |

背景色**两级取**：先查矢量填充，查不到再取**渲染像素的众数**。
版式自带的标题带、右上色块可能不是矢量而是图片，`get_drawings()` 看不到它们；
不落到像素上，就会把蓝底上的白字判成白底白字。

深色主题要改两处：`BG` 改成深色；
「卡片」的判据仍按填充矩形面积，不受底色影响。

## 闸门四：qa_layout（越界与空隙）

前两道管「有没有撞」，这道管「好不好看」。

| 常量 | 默认 | 含义 |
|---|---|---|
| `CT_TOP` / `CT_BOT` | 1.66 / 6.94in | 内容区上下沿 |
| `TOL` | 2.5pt | 越界判定容差（面板描边居中于路径） |
| `VOID_TOL` | 0.30in | 低于此值只记录 |
| `VOID_BAD` | 0.55in | 达到此值算「大量空隙」 |
| `TAIL_BAD` | 0.55in | 内容底部离页脚超过此值 = 提前收工 |
| `MIN_COVER` | 0.40 | 内容覆盖率下限 |

**以渲染后的真实墨迹为准**，不看源码里声明的框——声明的框高常大于实际墨迹，用它会漏判。

三条豁免（都是踩出来的）：

1. **LibreOffice 每页会导出一个整页白色矩形**（每页两次）。必须排除，
   否则「空隙」永远查不出来。
2. **三条以上高度相近的空隙是并列条目的节奏**，属刻意设计，不算缺陷。
3. **覆盖率阈值要按页型定**。纯文字页没有大色块，天生只有 45% 左右；
   阈值定到 0.45 就冤枉它们了。`MIN_COVER = 0.40` 是这个折中值。
   真要放宽，正确做法是给封面/结尾页这类版式配大底色（内置母版已经配了），
   而不是调低阈值。

## 渲染那一步的四个坑

`verify_all.py` 都处理了，但自己手敲 soffice 时要注意：

1. **`-env:UserInstallation=` 的值必须是 `file:/// 三个斜杠`。**
   写成 `file://C:/...` 时 soffice 会**静默产不出任何文件而 exit 仍为 0**，
   于是 PDF 一直停在旧 mtime 上，闸门拿旧 PDF 判新代码——最典型的假绿灯。
2. **转换前清掉残留 soffice 进程。** 残留进程会占住 UserInstallation 目录的锁，
   新转换立刻静默退出、不产出文件。
3. **写盘比进程退出慢。** 拿到 0 退出码之后还要等文件落盘。
4. **渲染前删掉旧 PDF。** 否则即使上面三条都出问题，闸门也会拿旧文件判新代码。

另外：**soffice 常常不在 PATH 上**，必须给全路径（见 `verify_all.py --soffice`）。
