# 图片处理规则

用户在开场交代场景时，**必须显式声明图片情况**。三种分支，处理方式完全不同：

---

## 分支一：无图

全部走纯排版页型。这条路线完全成立，而且往往比硬凑图更好看。

替代手段（按说服力排序）：

| 想表达 | 不用图片怎么做 |
|---|---|
| 有一组数 | 数据大数字页（`page-recipes.md` 第 5 种） |
| 几组方法/配置的对比 | 对照表页（第 4 种） |
| 逐层叠加的收益 | 原生柱状图（`kit.column_chart`，第 7 种） |
| 结构关系 | 分层页 / 三栏卡片页（第 6、8 种） |
| 具体案例 | 三栏卡片，每栏一段引文 + 一句推论 |

`scripts/build_deck.py` 的示例 deck 就是**通篇无图**的十页，可以直接当参照。

## 分支二：有图且已明确命名

> 例：文件名或说明里已经写清「鸡、鸭、鹅」「封面图」「架构图 A」这类语义。

**直接按用户指定的位置插入，不再做任何识别或改名。**

用户要同时给出**页码 + 页内位置**：

```
"第 7 页右侧放架构图 A，第 3 页整幅放封面图，鸡鸭鹅那三张放第 9 页三栏"
```

落到代码：

```python
fig(s, 6.36, 1.74, 6.31, "架构图A.png", "7", "系统整体架构与三条调用路径")
fig_fit(s, 0.0, 0.0, 13.33, 7.5, "封面图.png")
```

位置约定见下面的「页内位置速查」。**不要自作主张调整用户指定的位置**——
如果那个位置排不下（会压页脚、会盖住别的块），把冲突报给用户，让他选。

## 分支三：有图但命名模糊

> 例：`1.png` `2.jpg` `图3` `image1` 这类纯序号标识。

由**模型自己识别图片内容**，判断它讲的是什么，然后决定：放到哪一页、
放在页内什么位置、配什么图注。

**识别结论必须回报给用户确认**，写进生成日志/清单，不允许默默决定。

流程：

1. **逐张看图**（`read` 工具能直接看 png/jpg），写下一句话描述：它是什么、
   画的是什么、值不值得放进汇报。
2. **和页面大纲对齐**：这张图支撑的是哪一页的哪句话？找不到对应页就**不要放**
   ——一张不知道在讲什么的图，插进去只会让人分心。
3. **产出识别清单**，交用户确认后才写代码：

```markdown
## 图片识别清单（待确认）

| 文件 | 识别结论 | 拟放位置 | 拟配图注 |
|---|---|---|---|
| 1.png | 温度-功率双轴曲线，12 次运行的包络 | 第 8 页右侧 | 图 8　12 次运行的温度与功率曲线（峰值 43 ℃） |
| 2.jpg | 一张会议室照片，无科研信息 | — | 建议不使用 |
| 图3.png | 系统分层框图，4 层 + 模块名齐全 | 第 6 页整幅 | 图 6　系统分层：数据 / 索引 / 检索 / 生成 |

未采用的：2.jpg（无科研信息）
```

4. 用户改了就按用户的改；用户没改再继续。

---

## 图注规范

**来源、比例、序号统一。**

- **序号**：`图 N`，全 deck 连续编号，封面不计。从 `cap()` 出来就是统一的。
- **来源**：图注末尾或页面底部 `note()` 一行统一交代，不要每张图注都长串。
  论文原图、他人数据集截图**必须**注明出处，且注明「仅作学习汇报使用」之类。
- **比例**：见下，等比是硬要求。
- **字号**：图注 11.5pt（`图 N` 部分 Bold `BAND`，说明 `MUTED`）；整页统一来源行 10.5–11pt。

```python
fig(s, 6.36, 1.74, 6.31, "fig3_分层消融.png", "4", "七种配置的分层消融；标注集 19 条")
kit.note(s, M, 6.44, CW, "图源：某论文，SIGMOD 2020, Figure 1；某数据集 v1.2。仅作学习汇报使用。",
         size=10.5, h=0.38)
```

## 比例与间距（硬要求）

**原图不得拉伸变形。** 两条 API 都自动处理，用它们就对了：

```python
fig(s, x, y, w, name, no, text)          # 给宽，按原图比例算高，图注跟在下面
fig_fit(s, x, y, w, slot_h, name)        # 给槽（宽×高），在槽内等比缩放并双向居中
```

- `fig()`：图下沿 = `y + w / ar`；图注顶 = 图底 + `gap`（默认 0.07in）；返回图注底 y。
- `fig_fit()`：宽高都不合适时用它，它会先缩到槽内再居中，返回槽底 y。
- `kit.ar(path)` 用 pillow 实测原图宽高比，**不要手填常数**——
  手填对不上时闸门一和闸门二会同时把正常图判成「拉伸」。
- **图与正文的间距是常量**（`fig` 的 `gap` 默认 0.07in，图注高 0.30in）。
  同一份 deck 里图注位置忽高忽低，翻页时一眼能看出不齐。

闸门一和闸门二都会查这一项（放置比例 vs 原图比例，偏差 >2% 即报）。

## 页内位置速查（内置母版）

| 位置 | 几何 | 用法 |
|---|---|---|
| 整幅 | `0, 0, 13.33, 7.5` | 封面/过渡页，慎用（会盖掉版式装饰） |
| 满宽 | `M, y, CW` | 宽流程图、宽架构图，`fig()` |
| 右半 | `6.36, y, 6.31` | 左文右图的标准配法 |
| 左半 | `M, y, 5.90` | 右文左图 |
| 三栏内 | `X3[i] + 0.28, y, 3.34` | 每栏一图，`fig_fit(s, x, y, 3.34, 1.80, name)` |
| 图组 | 2 张并排：各 `5.85`，缝 `0.31` | 两张等宽并排，图注各自独立编号 |

选位置的三条经验：

1. **图的纵横比要配位置**。横图（ar > 2）配满宽或左右分栏，别塞进三栏的小槽；
   竖图（ar < 1）配整幅或左半。
2. **图不要高于 1.74in 起排**。上面是标题带和章节标签，压上去就是「越界」。
3. **图注底不要过 6.6in**。再往下就压页脚带了（`FOOT_TOP = 6.98`）。

## 图片目录

`kit.ASSET` 默认指向 `skill 包根/assets/`。用绝对路径或相对当前目录的路径也可以
（`kit.pic()` 先试原路径、再退回 `ASSET/<文件名>`）。

```python
kit.ASSET = Path("D:/我的项目/figs")     # 改图片目录
```

**不要把图片打包进 skill 包。** 论文原图、他人数据集截图都在用户自己手上，
skill 只提供处理规则与代码。
