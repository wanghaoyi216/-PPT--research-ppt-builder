# 讲稿与预设问答

讲稿的**唯一来源**是一份页面脚本里的 `kit.SCRIPT = {页码: (标题, 计时, 台词)}`。
它同时产出两样东西：

- **PPT 内嵌的演讲者备注**（`kit.notes(s, pn=页码)`，按页码从 `SCRIPT` 取台词）；
- **markdown 讲稿**（`kit.write_script_md(deck, qna=QNA)`，不传 `pages` 时直接由
  `SCRIPT` 生成）。

两份同源，所以不可能「幻灯片改了、讲稿没改」。**不允许各写各的。**

---

## 写法约定

1. **`say` 就是嘴上要说的话，不是要点。** 写完整句子，照读能顺下来。
   「① 关键词 ② 语义 ③ 图谱」是幻灯片上已有的东西，写进讲稿是浪费时间。
2. **括号里的短句是现场提示**（停顿、指屏、看提问人），读的时候跳过。
   `(指屏)` `(停顿)` `(指蓝色总纲带)` `(看提问人)`。
3. **数字照抄幻灯片原文**，含小数位与千分位，不改一位。讲稿里的数与页面不一致，
   是最容易被当场抓住、也最伤可信度的错误。
4. **第一次出现的专业词当场用大白话讲清**。听众可能是评审，不是本方向的人。
5. **不确定的口径不写，宁可少说。**
6. **不确定的数据纪律照实交代**，不要藏在页面上等提问（见下）。

## 计时

```python
kit.SCRIPT = {
    1: ("示例汇报 · 三层检索架构的落地与评测", "0:00–0:40", "各位老师好。…"),
    2: ("四步走完：问题、实验、结果、还差什么", "0:40–2:00", "先交一下底，今天四步。…"),
    ...
}
```

- `kit.SCRIPT` 定义在 `kit.py` 里，不是 `build_deck.py` 的局部变量——
  `notes(pn=…)` 和 `write_script_md()` 都要读它。

- 面向听众的**总时长**决定每页配额。经验值：封面 40s、纯文字页 60–90s、
  有图有表的主表页 90–120s、小结 90s、结尾 30s。
- 逐页区间要**首尾相接**（上一页的终点 = 下一页的起点），累计到总时长。
  排练一遍照着念，超了就砍页，不要加速念。

## 预设问答

每份讲稿末尾附一组**预设问答**：把提问方大概率会问的挑出来，
**按可如实作答的口径**写好。格式：

```python
QNA = [
    ("标注集才 19 条，这个数可信吗？",
     "绝对值不可信，我只看相对排序。19 条是两个人独立标完再对齐的结果，"
     "分歧全部留痕，但没有第三方终审，所以还没进论文。补终审是接下来第一件事。"),
    ...
]
kit.write_script_md(deck, qna=QNA, ...)
```

写预设问答的三条：

1. **只写有把握如实作答的。** 没把握的那题宁可不写，也不要写「这个待定」——
   写出来等于主动把问题递过去。
2. **先给边界再给数**。「绝对值不可信，我只看相对排序」比先甩数字更稳。
3. **答案第一句就要正面回答**，不要绕。「是的，样本量偏小」比「这个问题问得很好」
   省时间也更像在做事。

问答默认只进 markdown 讲稿，**不占幻灯片页**。要单独做一页，用
`page-recipes.md` 里的「Q&A 页的做法」。

## 口径纪律（写页面和写讲稿时都要守）

这是科研汇报里最容易翻车、也最值钱的一条。
**不确定的口径不写；自评数据要照实交代状态。**

必须在页面或讲稿里说清楚的（哪几条适用，看你自己的数据）：

| 事项 | 怎么写 |
|---|---|
| 标注/评测集是自评还是人工 | 「19 条是 AI 初标 + 盲评复核，**未人工终审**」 |
| 样本量小 | 「样本量小，**只看相对排序、不看绝对值**」 |
| 未做重复实验 | 「单款模型单次执行，**未做重复实验**」 |
| 耗时口径 | 「端到端墙钟时间，含生成与轮次开销，**不是纯推理时延**」 |
| 成本 | 「定价为**假设区间**」 |
| 用了什么模型 | 「云端前沿模型」（单次执行不写具体型号） |
| 分歧数据 | 分歧条数**全部留痕**，写明在留痕文件里 |
| 论文图 | 图注注明出处 + 「仅作学习汇报使用」 |

三条通用原则：

- **计划可以变，预告结果是自相矛盾。** 「下一步要做 A、B、C」是正常交代；
  「下一讲的结果是 X」等于当场露馅——那周还没做的事。
- **赢的照实写赢，输的照实写输。** 有一页专门写「对方在哪个工位全面胜出」，
  整份汇报的可信度会不一样。
- **口径的自我限制放在前面。** 放在路线页的底部，别等被问了才说。

---

## 讲稿要跟着页面走

改页面就要改讲稿，反之亦然。判定标准很简单：

> 讲稿里提到的每一个数字和页面上的对得上吗？每一个说法页面上找得到依据吗？

对不上就是漏改。`verify_all.py` 查不出这种错（它只查几何和颜色），
所以这一步只能靠人/模型自己过一遍。
